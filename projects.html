Project 03

Autonomous Web-Controlled Cart

Moet Thu, Qingyan Lin

Project Overview

The initial project idea was to design a follow-me cooler that would pair via Bluetooth with a user's smartphone, find its way to them using GPS and a compass, and deliver music via a Bluetooth speaker. However, based on available resources and a complexity analysis, the project was changed to a web-controlled cart. The cart no longer has the following GPS and compass functionality. Instead, it is connected to the web via its own access point, and the user can control it by pressing directional keys on a web page on the computer/phone, which then accesses the ESP32-C6 via a browser.

In the system, there are two ESP32-C6 boards that communicate using wired UART communication protocol. ESP32 #1 board controls the Wi-Fi module, motors, speed calculation using the IMU module, and audio playback using the speaker. ESP32 #2 takes instructions from ESP32 #1 and controls two OLED displays that function as indicators for turning and braking operations.

Planned vs. Actual Implementation

Components included in proposal, but not implemented in project:

  • GPS Module: Was originally intended to get live GPS coordinates from the user's phone using Bluetooth and follow autonomously. Not used due to use of web-based directional controls.
  • HMC5883L Compass: Was originally intended to give data via I2C to tell the cooler what direction it is facing. No longer used after removal of GPS module.
  • Bluetooth Speaker: Was originally intended to play songs while the robot follows you. Replaced by a basic speaker that plays sounds when activated via web UI.
  • Servo (Analog Output): Was originally included in the proposal for the lid of the cooler. No longer required after turning the project into a cart platform.
  • ON/OFF Switch (Digital Input): Was originally intended to switch on the ability to follow autonomously. Replaced by an ON/OFF switch on the website.
  • Speedometer (uLCD): Was originally going to be used to show IMU Velocity of robot. Not required anymore due to boot delay time in OLED.

Components and Their Roles

ESP32-C6 #1 – Main Controller

Generates a WiFi hotspot and delivers a basic HTTP web page featuring directionally oriented buttons and an ON/OFF button. In case of pressing the buttons, fetch() calls are made to the ESP32 responsible for moving the motors and sending instructions to ESP32 #2 via UART. The IMU is also monitored, and the speaker sounds are played when power is turned on and off.

  • Motor Driver (TB6612FNG) - Receives control input signals from ESP32 #1 and delivers the greater current requirement of the 12V DC motors. Selected over the L298N because of higher efficiency and reduced voltage drop. It was also available in the lab room.
  • IMU Module (ICM-20948) - Uses I2C protocol to interface with ESP32 #1. The z-axis accelerometer value is processed by applying a gravity offset correction factor and exponential decay to determine the speed of the cart. The speed information is transmitted to ESP32 #2 every 500ms through UART.
  • Breadboard Speaker - Connected to a PWM GPIO on ESP32 #1 using ledcWriteTone(). Plays a four-tone rising chime when the cart is turned on and a falling chime when turned off.

ESP32-C6 #2 – Display Controller

Receives UART instructions from ESP32 #1 and controls two OLED displays through the following logic:

  • LEFT: blinking of the left screen
  • RIGHT: blinking of the right screen
  • STOP: blinking of the left and right screens
  • Dual OLED (SSD1306) - Attached to both sides of the cart and connected to ESP32 #2 using the I2C protocol (I2C addresses 0x3C and 0x3D). Used as turn indicators and brake lights by displaying animated text through the U8g2 library.

Features Included

Below are the features we decided to include in our project:

  • Using a new part not covered in the labs (I2C OLED)
  • Digital Output (motor, motor driver)
  • Wired ESP32 Communication
  • PWM Output or Analog Output (Motor, mortar driver)
  • Serial Communication (UART between 2 ESP32s)
  • Bluetooth/Wi-Fi (esp32 and phone)
  • I2C Communication (IUM, OLED screen)
  • Fully Battery Powered (4.5V and 12V)

Problems Encountered

We 3D-printed a hub adapter to connect the DC motor shafts to the cart wheels. Unfortunately, the first adapter had to be broken after the cart crashed into a chair. However, further adapters were made from resins that proved to be much stronger. The motor's direction towards forward, backward, left, and right directions was incorrectly determined based on how the motors' wires were connected. Solved by checking the motor direction flags in setMotorA() and setMotorB(). Since both the uLCD and UART to ESP32 #1 needed Serial1, this problem was resolved by using UART and another HardwareSerial on other GPIO pins. The problem with non-working OLED displays was that 5 seconds were needed for the uLCD to boot up, and removing the uLCD from the program solved the issue.

Comparison to Real-World Embedded Systems

In terms of product design, our plan is to create a robot similar to Hackster.io's follow-me cooler, but their project works with Arduino UNO and a Bluetooth chip in addition to its GPS. We used a Wi-Fi-based browsing system rather than a GPS tracking system because our robot can be operated on any device without having to attach a remote controller.

Future Improvements

A voltage reading from a resistor divider on the battery to the ADC pin will help the website issue a warning when power is running low. Printing all structural parts in resin or PETG will ensure they can withstand continuous motor loads. Connecting Bluetooth audio will make it possible to listen to music.
